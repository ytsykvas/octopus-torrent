# Версії інструментів і залежностей, політика оновлення

**Статус:** `accepted`  
**Дата:** 2026-10-14, політику уточнено 2026-10-15 рішенням власника  
**Задача:** [003](../../tasks/003-wails-macos-build-spike.md)  
**Пункт реєстру:** O2 із [базового опису](project-baseline.md#6-реєстр-відкритих-рішень) — частково: Go, Wails, Node.js, frontend. Версію anacrolix/torrent фіксує [007](../../tasks/007-engine-api-lifecycle-spike.md), SQLite-драйвер — [008](../../tasks/008-sqlite-driver-durability-spike.md); обидві — за політикою нижче.  
**Вимоги:** AI-07, REL-01, STACK-05

## Питання

1. Який набір версій Go, Wails v2, Node.js і frontend-залежностей узяти зараз, щоб `.app` відтворювано збиралася з чистої копії.
2. Як тримати стек актуальним, не наражаючи проєкт на щойно опубліковані зламані або шкідливі релізи (атаки на ланцюг постачання).

## Рішення

### Політика версій (обов’язкова для всіх наступних задач)

| Що | Правило |
|---|---|
| **Сторонні пакети** — npm і Go-модулі, **включно з транзитивними** | Остання стабільна версія, опублікована **щонайменше 14 днів тому**. Пре-релізи (`alpha`, `beta`, `rc`) не використовуються. |
| **Інструменти** — Go, Node.js з офіційних каналів (go.dev / Homebrew) | Patch-релізи вже прийнятої лінії ставляться одразу: вони часто закривають вразливості, а канали підписані й мають контрольні суми. Нова minor- або major-лінія — лише після 14 днів. |
| Транзитивні Go-залежності | Версії, які обирає Go MVS із вимог прямих залежностей (як їх випускає автор бібліотеки). Примусово оновлюється лише транзитивний модуль із відомою вразливістю. |
| npm install-скрипти | Заборонені за замовчуванням: явний список у `allowScripts` (`frontend/package.json`). Зараз `fsevents: false` — пакет постачається з готовим бінарником, скрипт не потрібний. |
| Актуальність | Під час кожної задачі, що змінює залежності, і регулярною перевіркою з [004](../../tasks/004-reproducible-check-commands.md) (`npm outdated`, `go list -m -u all`, вік релізів, `npm audit`, `govulncheck`): версію, що вийшла з 14-денного карантину, оновлювати, а не відкладати. |
| Wails v3 | Лишається `beta` (`v3.0.0-beta.29` від 2026-10-13). Перехід — окреме рішення власника після стабільного релізу ([вимоги §1](../../PROJECT_REQUIREMENTS.md#обраний-стек)). |

**Технічне забезпечення:** `frontend/.npmrc` → `min-release-age=14`: npm сам не встановить молодшу версію жодного пакета, включно з транзитивними (npm ≥ 11.20). Для Go аналогічної опції немає — вік модулів перевіряється за часом публікації в `proxy.golang.org` (див. «Перевірені підстави»); автоматизацію робить 004.

## Розглянуті альтернативи

| Варіант | Переваги | Недоліки | Чому не обрано |
|---|---|---|---|
| Завжди найновіші версії без паузи | Максимальна свіжість | Щойно опублікований зламаний або шкідливий пакет потрапляє в проєкт до того, як його виявлять | Відхилено власником 2026-10-15 як вразливість |
| Пауза 14 днів і для patch-релізів Go/Node | Одне правило для всього | Затримує виправлення безпеки інструментів; потребує ручного встановлення старіших версій поза Homebrew | Рішення власника: patch-релізи інструментів — одразу |
| `go get -u all` (усі транзитивні Go-модулі до найновіших) | Найсвіжіші транзитивні версії | Комбінація, яку автори Wails не тестували (стрибки v0→v1, напр. lipgloss, glamour); ризик зламати CLI/dev-режим непомітно для тестів | Рішення власника: транзитивні — за MVS, вразливі — примусово |
| Глобальний `go install …/wails@v2.16.0` | Стандартна інструкція Wails | Версія CLI не прив’язана до репозиторію; потрібен `~/go/bin` у `PATH` | `go tool` дає ту саму CLI, закріплену в `go.mod` |
| TypeScript 6.0.3 | Найширша сумісність | Застаріваюча лінія | 7.0.2 перевірено з Vite 8 і Vitest 5 |

## Перевірені підстави

Середовище: Apple M4, macOS 27.0.1, Xcode Command Line Tools 2418 ([звіт 003](../verification/003-wails-macos-build-spike.md)).

- **Вік релізів (2026-10-15, межа 2026-09-30):** перевірено час публікації кожної версії з `frontend/package-lock.json` (159, registry.npmjs.org) і з `go list -m all` (142, proxy.golang.org) — `pass`, молодших немає; найновіші — `chai@6.3.0` (2026-09-30) і `wails/v2@v2.16.0` (2026-09-14).
- **Вразливості:** `npm audit` — `found 0 vulnerabilities`; `govulncheck ./...` — `No vulnerabilities found`.
- `go tool wails doctor` — `SUCCESS`; `go tool wails version / init / generate module / build / dev` працюють без глобального `wails`.
- Тести, 100% покриття, `tsc --noEmit`, збірка й клік у справжній `.app` — `pass` на цьому наборі.
- Збірка з чистої копії відстежуваних файлів (`npm ci` з lockfile під `min-release-age=14`) — `pass`; бінарник без підпису й frontend-бандл побайтово ідентичні збірці з робочого дерева.

**Виправлена помилка:** перша редакція цього ADR (2026-10-14) декларувала правило 14 днів, але взяла Go 1.27.2 у віці 12 днів і не перевіряла транзитивні npm-пакети. Тепер вік перевіряється для всіх пакетів, а для інструментів діє окреме правило вище.

Не перевірено: інші версії Node.js у межах `>=22.12.0`.

## Наслідки

- Команди в [README](../../README.md#команди-збірки-й-перевірок) використовують `go tool wails`; глобальний Wails CLI не потрібен.
- Додавання або оновлення залежності — разом з оновленням таблиці «Поточний набір» і повторною перевіркою віку, вразливостей, тестів і `.app`.
- [004](../../tasks/004-reproducible-check-commands.md) включає в єдину локальну перевірку: вік релізів, `npm outdated` / `go list -m -u all` (звіт про доступні оновлення), `npm audit`, `govulncheck`.
- Відоме попередження лінкера `object file … built for newer 'macOS' version (13.0) than being linked (11.0)` — Wails лінкує з мінімальною версією 11.0, Go 1.27 збирає об’єкти для 13.0; на запуск не впливає. Цільова система — [macos-target.md](macos-target.md).
